# Resonaura — Полная инвентаризация сценического сетапа

> Это внутренний рабочий документ ("каждый винтик"), а не райдер для площадки (для площадки — `rider.md` в корне).
> Цель: зафиксировать текущую реальность сетапа настолько подробно, насколько возможно, чтобы на основе этого
> проектировать модель данных (устройства/порты/кабели/питание/аксессуары) для конструктора.
>
> Статус пунктов:
> - ✅ — подтверждено, есть железка / решение принято
> - ❓ — пока не знаю точно (например, состав/питание педалей). Это **не блокер**: граф-интерфейс — это просто железки и кабеля,
>   их можно завести приблизительно и поправить в любой момент через GUI. Ничего здесь не обязано быть "зафиксировано как факт"
>   до реализации — модель данных должна просто позволять редактировать устройства/кабели/питание когда угодно.
> - 🔜 — будущее расширение (big set), пока не в текущем сетапе, но должно быть заведено в инвентарь как "не активная" единица

Дата фиксации: 2026-07-20. Составлено по мотивам факапа с мониторингом плейбеков на первом лайве.

## 1. Мой (гитарный) сигнальный тракт — сцена слева

### 1.1 Инструмент → педалборд → звуковуха

```
Моя гитара
  → инструментальный кабель (красный)
  → Педалборд Harley Benton SpaceShip 60 (рабочее название "Starship" — уточнить точную модель/размер)
  → TRS 1/4" x 2 (стерео/два моно-выхода педалборда)
  → Behringer UMC404HD (вход 1/2, +48V не нужен, инструментальный/линейный уровень)
```

- Питание педалборда: **Harley Benton PowerPlant ISO-12 Pro** (изолированный мультиблок).
  - ❓ Состав педалей на борде пока не описан поштучно — нужен интерактивный список (см. раздел 6 "Инвентарь педалей").
  - Для каждой педали в будущем интерфейсе нужно фиксировать: название, модель, тип (моно/стерео), наличие presets/smart-режимов, требуемое питание (мА, В, полярность, разъём), позиция в цепи (порядок сигнала), патч-кабели до соседних педалей.
- Питание UMC404HD: 5V DC, 1A, штекер 5.5×2.1мм. ⚠️ Полярность спорная в даташитах — фактически Center Negative с диодной защитой от переполюсовки. В конфиге ставим строго Center Negative и не разрешаем AC-адаптеры.
- USB-подключение UMC404HD → ноут/интерфейс: USB Type-A → Type-B, запитан от удлинителя Anker (Type-A порт удлинителя).

### 1.2 Выходы UMC404HD

```
UMC404HD Main Out (XLR L/R)
  → 2 x XLR (мои, 6м, синий + зелёный)
  → Стейджбокс площадки (пара, лево/право)

UMC404HD Phones Out (1/4" TRS, стерео)
  → кабель на вход Behringer MX400 (моно, TS)
    Стерео-джек просто втыкается в моно-вход — берётся левый канал. Для чистого мониторинга-в-уши
    это ожидаемо и нормально, переходник/сумматор не нужен, адаптация не требуется.
```

### 1.3 Мой личный мониторинг (добавлено ПОСЛЕ первого лайва — фикс провала с плейбеками)

Причина добавления: на первом концерте полагались на локальный мониторинг площадки для плейбеков — их не было слышно, сбились в важной песне. Решили: **выделенный личный monitor-микс мимо площадки**.

```
Источник 1: Playback-звуковуха (MOTU UltraLite mk3), линейный/TS выход
  → длинный TS инструментальный моно кабель
  → Behringer MX400 (канал 1), + БП MX400 (см. 5.3, отдельный, НЕ от педалборда)

Источник 2: UMC404HD Phones Out
  → кабель на канал 2 MX400 (стерео в моно, берётся левый канал — см. 1.2, это ок для мониторинга)

MX400 Out (моно, TS, ~80 Ом)
  → Palmer Monicon Classic (пассивный monitor controller, режим MONO)
  → мои наушники
```

- Palmer Monicon Classic — полностью пассивный, питание не требуется.
- ⚠️ Правило по Palmer Monicon: **нельзя одновременно использовать Combo(XLR/TRS) и mini-jack 3.5мм входы одновременно** — грозит земляной петлёй. У нас используется только Combo/TRS вход с выхода MX400, mini-jack не используем — зафиксировать как ограничение в валидаторе.
- MX400 требует своего **отдельного** блока питания 12V DC, Center Positive. ❌ **ИСПРАВЛЕНИЕ предыдущего ресёрч-отчёта**: MX400 НЕ висит на педалборде и НЕ запитан от Harley Benton PowerPlant ISO-12 Pro. У него всегда был отдельный собственный БП. Предыдущий вывод ИИ про "нужен инвертирующий кабель между ISO-12 Pro и MX400" — неверная догадка, растущая из неверной посылки, что MX400 стоит на борде. В инвентаре MX400 должен быть отдельным power root, не дочерним узлом педалборда.

## 2. Тракт Дани-вокала (вокал + иногда гитара) — центр сцены

### 2.1 Вокал

```
Микрофон Даня-вокала (наш, XLR кабель красный — наш, не площадки)
  → Universal Audio Volt 276, вход 1 (Combo XLR/TRS, mic level, +9dBu, 3кОм)
    Питание Volt 276: USB-C → Type-C (5V DC, от удлинителя Андрея, порт Type-C)

Volt 276 output (1) → удлинитель для наушников + переходник TRS 1/4" → TRS 1/8"
  → IEM-наушники Даня-вокала (СВОИ, у него есть собственные IEM)
```

⚠️ **Важно про мониторинг Дани-вокала (текущее реальное состояние, не план):** IEM подключены **напрямую в звуковуху** (Volt 276 output 1), без микшера — микшер (см. 2.3) ещё не куплен. Сейчас Даня-вокал слышит в ушах **только себя** (свой канал с Volt 276), не полный мониторный микс. Это нормальное текущее состояние, не баг и не недоделка, которую нужно "исправить перед тем как заводить в конфиг" — просто так оно есть сейчас, и это должно быть representable в графе как есть (прямая связь звуковуха → IEM, без промежуточного микшера).

```
Volt 276 output (2) → длинный TS 1/4"
  → Behringer FEX800 (вок-процессор эффектов, стерео IN/OUT, требует AC 9V 750mA — ⚠️ строго AC, НЕ DC, отдельный родной адаптер)
  → Стейджбокс площадки (джековый вход — под вопросом, есть ли у площадки джек-вход в стейджбоксе)
```

### 2.2 Гитара Дани-вокала (используется не на всех песнях)

```
Гитара Даня-вокала
  → инструментальный кабель
  → 3 педали (❓ состав пока не заполнен — завести как есть, дополнить в GUI когда будет под рукой)
  → инструментальный кабель
  → Комбик Даня-вокала (Egnater Tweaker 40W, по данным rider.md), + сетевое питание
```

❓ **Питание 3 педалей Дани-вокала — пока не помню точную конфигурацию.** Не блокер, просто фиксируем как известный неполный факт (граф можно поправить в любой момент, когда уточнится):
1. Один совмещённый (комбинированный) блок питания на все 3 педали (мультиблок, аналогично ISO-12 Pro).
2. Два отдельных БП: один запитывает 1 педаль напрямую, второй — через разветвитель (splitter/daisy-chain 1-в-2) запитывает оставшиеся 2.
3. Один БП с разветвителем 1-в-3 (daisy-chain на все три педали).

→ В модели данных нужен generic `PowerSplitter` (1 IN → N OUT), который можно вставлять между БП и педалью/группой педалей — тогда любой из трёх вариантов заводится как обычное редактирование графа, без специальной "заглушки для неизвестного".

- Подзвучка комбика Дани-вокала микрофоном: по факту первого лайва — не успели поставить. По `rider.md` в целевом райдере уже заложено: комбик → Sennheiser e835s → стейджбокс, канал "Vocalist's Guitar Amp Mic". Целевое состояние, физически ещё не обкатано живьём.

### 2.3 Микшер Дани-вокала (план на будущее, ещё не куплен)

```
❓ (не куплено, план) Маленький стерео-микшер Дани-вокала
  ← выход "наушники" вокальной звуковухи (Volt 276) кабелем
  ← TS/TRS кабель с playback-звуковухи (MOTU)
  → IEM Дани-вокала через удлинитель для наушников
```

Статус: пока не решил, будет ли покупать. До покупки актуальна прямая схема из 2.1 (Volt 276 → IEM напрямую, слышит только себя). Заводить в инвентарь как "запланированное, не приобретённое" оборудование (статус `planned` / `not_owned`), не подключённое в текущий активный граф.


| Удлинитель | Сторона | Что запитано (AC розетки) | Что запитано (USB) |
| --- | --- | --- | --- |
| Anker #1 | Сторона Андрея (слева) | БП UMC404HD (если не через USB bus), БП MX400, БП педалборда (ISO-12 Pro), Govee-лампа | Type-C порт → Volt 276 (по кабелю к Дане-вокалу, физически удлинитель стоит у Андрея) |
| Anker #2 | Сторона Дани-вокала / центр / плейбеки | БП MOTU UltraLite mk3, БП FEX800 (AC 9V, родной адаптер), БП комбика Дани-вокала | Type-A порт → возможный будущий стерео-микшер Дани-вокала (❓ план) |

Ограничение USB-модуля Anker: суммарно ≤15W при одновременном использовании всех USB-портов (5V/3A общий бюджет), Type-C порт индивидуально до 20W PD. Это нужно учитывать как лимит в валидаторе питания для узлов, подключаемых через USB-порты удлинителя (в первую очередь Volt 276: 5V/5W — укладывается с большим запасом).

### 5.2 Изолированный DC-контур педалборда (только мой борд)

**Harley Benton PowerPlant ISO-12 Pro**, закреплён под HB SpaceShip.

- Группа выходов 1–9: 9V DC, до 300мА, Center Negative.
- Группа выходов A/B/C: переключаемые 9/12/18V DC, до 500мА, Center Negative.
- Глобальный лимит: ≤27W суммарно на все активные выходы.
- ❌ MX400 **НЕ** висит на этом блоке (см. исправление в 1.3). На борде — только сами гитарные педали (состав — раздел 6, TBD).
- CME MIDI Thru5 WC (когда используется, см. раздел 7) — кандидат на подключение сюда: 9V, ток мизерный (~2.2мА), Center Negative, отлично ложится на группу 1–9.

## 6. Инвентарь педалей — требования к интерфейсу (ещё не заполнено пофакту)

Нужен раздел в GUI, куда можно интерактивно добавлять педали (мои — на HB SpaceShip, и педали Дани-вокала — 3 шт., ❓ состав тоже пока не заполнен) со следующими полями на каждую единицу:

- Название/модель (свободный текст + опционально ссылка/фото)
- Тип сигнала: **моно** / **стерео** (in и out раздельно — бывают моно-in/стерео-out и наоборот)
- "Умная" ли педаль: наличие пресетов, их количество, поддержка сохранения пресетов, MIDI-управление пресетами (channel/PC/CC), наличие "smart"-режимов (адаптивных/авто-режимов)
- Требуемое питание: напряжение, ток (мА), полярность, тип разъёма (обычно DC barrel 5.5×2.1 или 2.1×5.5 центр-минус, но фиксировать явно, не считать дефолтом)
- Позиция в цепи сигнала (порядок относительно других педалей на борде)
- Патч-кабели до соседей: длина, тип (TS обычно), физическая пара (flat patch / обычный инструментальный)
- Фото/картинка (аплоад или URL)

Аналогично зафиксировать сами физические элементы борда, которые тоже часть инвентаря, а не только "железки со входами/выходами":

- Педалборд как контейнер (модель, размеры, макс. нагрузка по весу/питанию)
- Липучки/velcro крепления педалей к борду (по сути "аксессуар без портов", но с привязкой родитель→ребёнок к конкретной педали)
- Патч-кабели как отдельный тип кабеля (короткие, часто угловые джеки) — уже частично покрывается `CableType`, но нужно отличать патч-кабель от обычного инструментального по длине/форм-фактору для визуализации
- Гитарные стрепы (ремни) — тоже просто инвентарная единица без портов, привязана к инструменту
- Разветвители/сплиттеры питания (daisy-chain) как отдельная сущность с 1 входом и N выходами, которую можно вставлять между БП и педалью/группой педалей — это то, чего критически не хватает, чтобы корректно смоделировать ❓ вопрос из раздела 2.2 (питание 3 педалей Дани-вокала)

## 7. MIDI-инфраструктура (для будущего большого сета, пока не используется в текущем составе)

- **CME MIDI Thru5 WC**: 1 MIDI IN, 5 MIDI OUT (быстрые оптопары), опциональный модуль WIDI Core (Bluetooth MIDI BLE). Питание: USB Type-C (5V) ИЛИ 9V DC Center Negative (например, с ISO-12 Pro группа 1–9) — на выбор, взаимоисключающе.
- 3x качественных MIDI-кабеля (5-pin DIN), состав/модели не зафиксированы отдельно — завести как generic инвентарь "MIDI Cable" с длиной.
- 🔜 Статус: сейчас не участвует в активном сетапе (текущий сет проще), закладывается на будущий больший сет. В инвентаре — как unassigned/inactive оборудование, доступное для добавления в сетап.

## 13. Импликации для модели данных (кратко, не техспека — просто заметки на будущее)

Этот раздел — не про реализацию, а фиксирует, какие сущности/поля точно понадобятся исходя из вышеописанного, чтобы при проектировании TypeORM-схемы не забыть:

- Питание: нужен тип `PowerSplitter`/`DaisyChain` (1 IN → N OUT), не только точка-в-точку БП→устройство — иначе вопрос №4 из раздела 12 нельзя корректно смоделировать ни в одном из трёх вариантов.
- Полярность источника питания должна поддерживать значение `ANY` (для MOTU UltraLite mk3), не только `POSITIVE`/`NEGATIVE`.
- Тип тока (`AC`/`DC`) на уровне порта питания — обязателен как отдельное поле от напряжения, иначе нельзя заблокировать некорректное подключение FEX800 к DC-адаптеру.
- Статус оборудования в инвентаре — минимум три состояния: `owned_active` (используется сейчас), `owned_inactive` (есть, но не в текущем сетапе — MIDI Thru5, big set), `planned_not_owned` (микшер Дани-вокала). Просто boolean "есть/нет" недостаточно.
- Аксессуары без портов (тюнер, стрепы, липучки, кейсы) — отдельный класс сущности, привязываемый к родительскому устройству, но не участвующий в графе кабелей.
- Педаль как устройство: раздельные поля in/out для моно/стерео, наличие пресетов/smart-режимов (см. раздел 6).
- "Control link" (Wi-Fi/BLE управление, например Govee) — связь, которая не является ни аудио-, ни MIDI-, ни силовым кабелем, но всё равно связь между узлами графа.
- Возможность одного устройства (UMC404HD) быть частью нескольких сетап-профилей (обычный сет / big set) — вероятно, через отдельные `Setup`-сущности, где устройство переиспользуется, а не дублируется.
- Ничего не должно требовать "полноты" перед сохранением: устройство без указанных педалей, кабель без питания, разъём без подтверждённого переходника — всё это валидные промежуточные состояния графа, а не ошибки. Валидация (например power budget) должна предупреждать, а не блокировать сохранение неполных данных.
